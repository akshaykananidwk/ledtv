# HotelCast API Documentation

Base URL: `https://<your-domain>/<install-path>/api`

All responses are JSON (`Content-Type: application/json; charset=utf-8`), UTF-8 throughout
(Gujarati text is returned as-is, not escaped).

Every response has the envelope:

```json
{ "ok": true,  "data": { ... } }
{ "ok": false, "error": { "code": "INVALID_TOKEN", "message": "Human readable message" } }
```

HTTP status codes: `200` success, `400` validation error, `401` auth failure, `403` forbidden,
`404` not found, `409` conflict, `429` rate limited (has `Retry-After` header), `500` server error.

If Apache `mod_rewrite` is unavailable, every endpoint can also be called as
`/api/index.php?r=device/register` (the `r` parameter holds the route).

## 1. Device (Android TV) API

### Authentication

1. A TV calls `POST /api/device/register` once with the hotel **registration key**
   (shown in *Admin → Settings → Devices*). The server returns a `token`.
2. Every subsequent call sends the headers:

```
Authorization: Bearer <token>
X-Device-Id: <device_uid>
```

The token is random (256-bit) and stored on the server only as a SHA-256 hash. A token is bound
to one `device_uid`; re-registering a device rotates its token. Admins can revoke a device from
the Rooms page — the TV then gets `401 INVALID_TOKEN` and returns to its setup screen.

Device endpoints are rate limited to **120 requests / minute / device** (polling at 5 s = 12/min).

---

### POST /api/device/register

Request body (JSON):

| field              | type   | required | notes                                             |
|--------------------|--------|----------|---------------------------------------------------|
| `device_id`        | string | yes      | UUID generated by the app, kept in SharedPreferences |
| `room_number`      | string | yes      | e.g. `"101"`. Room is auto-created if missing and setting `auto_create_rooms` = 1 |
| `registration_key` | string | yes      | Hotel registration key                             |
| `app_version`      | string | no       | e.g. `"1.0.0"`                                     |
| `app_version_code` | int    | no       | e.g. `1`                                           |
| `android_version`  | string | no       | e.g. `"11"`                                        |
| `model`            | string | no       | `Build.MODEL`                                      |
| `ip_address`       | string | no       | LAN IP of the TV                                   |

Response `data`:

```json
{
  "token": "f3a9...64 hex chars",
  "device_id": "2b1c5d9e-...",
  "room": { "id": 12, "number": "101", "name": "Deluxe 101", "floor": "1" },
  "poll_interval": 8,
  "heartbeat_interval": 60,
  "settings_pin_hash": "sha256 hex of 4 digit PIN"
}
```

Errors: `INVALID_REGISTRATION_KEY` (401), `ROOM_NOT_FOUND` (404), `VALIDATION_ERROR` (400).

---

### GET /api/device/command/{device_id}

The TV polls this every `poll_interval` seconds (default 8, admin configurable 3–60).

Query parameters:

| param  | notes |
|--------|-------|
| `hash` | the `hash` of the content the TV is currently showing. If it differs from the server's current content hash, the full `content` object is included in the response. |
| `wait` | optional long-poll seconds (0–25). Only honoured if the admin enabled long polling. |

Response `data`:

```json
{
  "server_time": "2026-10-05T18:30:00+05:30",
  "poll_interval": 8,
  "content_hash": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b",
  "content_changed": true,
  "content": { ...Content object, only when content_changed... },
  "commands": [
    { "id": 551, "command": "REBOOT", "payload": {} },
    { "id": 552, "command": "UPDATE_APP", "payload": { "url": "https://.../api/device/apk/7", "version_code": 7, "version_name": "1.2.0", "sha256": "..." } }
  ]
}
```

Commands are returned until they are acknowledged via `/api/device/ack` (delivery is at-least-once;
the TV must de-duplicate by `id`). Commands not acked within 24 h expire.

#### Command types

| command          | payload                                       | TV behaviour |
|------------------|-----------------------------------------------|--------------|
| `SHOW_CONTENT`   | `{}`                                          | Re-fetch content immediately (`GET /api/content/{room_id}`) and switch display. |
| `REBOOT`         | `{}`                                          | Ack first, then reboot the device (device-owner / root) or restart the app if reboot is not permitted. |
| `CLEAR_CACHE`    | `{}`                                          | Delete cached media + cached content JSON, then re-fetch. |
| `UPDATE_APP`     | `{url, version_code, version_name, sha256}`   | Download APK (with the auth headers), verify sha256, install, relaunch. |
| `SCREEN_OFF`     | `{}`                                          | Show a black screen (room "off"). |
| `SCREEN_ON`      | `{}`                                          | Resume normal content. |
| `RELOAD`         | `{}`                                          | Restart the main activity. |
| `PING`           | `{}`                                          | Ack only (connectivity test). |

---

### POST /api/device/ack

```json
{ "command_id": 551, "status": "acked", "message": "Rebooting" }
```

`status` is one of `delivered`, `acked`, `failed`. Response `data`: `{ "command_id": 551, "status": "acked" }`.

### GET /api/content/{room_id}

Returns the Content object currently scheduled for a room. A device may only read its own room.

### Content object

```json
{
  "hash": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b",
  "generated_at": "2026-10-05T18:30:00+05:30",
  "mode": "assigned",
  "screen_on": true,
  "room": { "id": 12, "number": "101", "name": "Deluxe 101", "floor": "1" },
  "hotel": { "name": "Hotel Dwarka Palace", "logo_url": "https://.../uploads/branding/logo.png" },
  "playlist": { "id": 3, "name": "Morning loop", "transition": "fade", "loop": true },
  "items": [ ContentItem, ... ],
  "overlay": {
    "clock": true,
    "clock_format": "hh:mm a",
    "weather": { "enabled": true, "city": "Dwarka", "temp_c": 31, "condition": "Clear", "icon": "☀" },
    "ticker": { "text": "Mangla Aarti at 6:00 AM | મંગળા આરતી સવારે ૬:૦૦", "speed": 5, "bg_color": "#000000", "text_color": "#FFD700" },
    "logo": true
  },
  "emergency": null
}
```

`mode` is one of:

| mode        | meaning |
|-------------|---------|
| `emergency` | an emergency broadcast is active — `items` holds one announcement; the TV must show it full screen, above everything |
| `scheduled` | a time-window broadcast is currently active for this room |
| `assigned`  | content assigned directly to the room |
| `group`     | content assigned to one of the room's groups |
| `default`   | hotel default content |
| `off`       | the room is switched off — show a black screen (`screen_on` = false) |
| `empty`     | nothing to show — show the hotel logo / welcome screen |

When `emergency` is not null it is: `{ "id": 9, "title": "...", "message": "...", "bg_color": "#B00020", "text_color": "#FFFFFF" }`.

### ContentItem

Common fields: `id`, `type`, `title`, `duration` (seconds the item stays on screen in a playlist;
`0` = until the item ends / forever for single items).

| type           | extra fields |
|----------------|--------------|
| `image`        | `url` |
| `video`        | `url`, `loop` (bool), `mute` (bool) |
| `stream`       | `url` (HLS `.m3u8`, RTSP `rtsp://`, DASH or progressive), `mute` |
| `timetable`    | `html` (complete HTML document, render in WebView), `refresh_sec` |
| `announcement` | `text`, `subtitle`, `style` (`fullscreen` \| `marquee`), `bg_color`, `text_color`, `font_size` (sp) |
| `html`         | `html` (complete HTML document) |
| `url`          | `url` (open in WebView) |
| `youtube`      | `url` (original), `embed_url` (open in WebView, autoplay) |
| `clock`        | `style` (`digital` \| `analog`), `bg_color`, `text_color` |

Media URLs (`image`, `video`) point to `/uploads/media/YYYY/MM/<random>.ext` (or the configured CDN base
URL + the same path). File names are random 96-bit tokens; `uploads/.htaccess` disables script execution,
directory listing and HTML/SVG/JS files. The TV should cache media files locally keyed by URL
and keep the last Content object on disk to show while offline.

### GET /api/device/apk/{apk_id}

Downloads an APK (device auth required). Response is `application/vnd.android.package-archive`.

### GET /api/health

Public. `{ "ok": true, "data": { "status": "ok", "version": "1.0.0", "db": true, "time": "..." } }`.
Used by the updater's health check and by uptime monitors.

## 2. Admin AJAX API

Used by the admin panel. Session cookie authentication + `X-CSRF-Token` header for every non-GET
request. Base: `/admin/ajax.php?action=<name>`.

| action                | method | role            | description |
|-----------------------|--------|-----------------|-------------|
| `dashboard_stats`     | GET    | any             | room/device counts, online/offline, recent activity |
| `room_status`         | GET    | any             | live status for every room (used for auto refresh) |
| `send_command`        | POST   | manager (+staff for SHOW_CONTENT) | `{command, target_type, target_ids[]}` |
| `emergency_start`     | POST   | staff+          | `{title, message, target_type, target_ids[]}` |
| `emergency_stop`      | POST   | staff+          | clears all active emergencies |
| `preview_content`     | GET    | any             | `content_id` or `playlist_id` → Content object preview |
| `update_check`        | POST   | super_admin     | checks GitHub (latest commit, version, changed files, commits) |
| `update_run`          | POST   | super_admin     | runs the full update; returns step log |
| `update_status`       | GET    | super_admin     | live log of the running update (polled every 1.5 s) |
| `update_health`       | POST   | super_admin     | full health check + system report |
| `rollback`            | POST   | super_admin     | `{history_id}` or `{backup, restore_db}` |
| `update_backup_create`| POST   | super_admin     | `{include_uploads}` |
| `update_backup_delete`| POST   | super_admin     | `{name}` |
| `update_backup_upload`| POST   | super_admin     | multipart `backup` (.zip) |
| `update_backup_download` | GET | super_admin     | `name`, `token` (CSRF token) |

The update/backup actions live in `admin/ajax_update.php` (also reachable through `admin/ajax.php`).

Roles: `super_admin` > `manager` > `staff`.
